# docmost v0.96.0 Upstream Merge — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the docsbolt fork up to upstream `docmost/docmost` v0.96.0 while preserving every fork-specific change (EE features, Portainer infrastructure, `boltplan` rename) unless the user explicitly authorizes the upstream replacement.

**Architecture:** A clean `git merge` of the `v0.96.0` annotated tag into a dedicated `merge/v0.96.0` branch, followed by systematic, category-driven conflict resolution. We use `git merge-tree` (read-only) to pre-classify every conflict, then resolve in passes by category (identity/version → infra/lockfile → core code → features flags → translations). A final green build + dev-server smoke + EE endpoint smoke closes the loop. No `git rebase` — we want a true merge commit so the divergence history stays auditable.

**Tech Stack:** Git, pnpm 11.x, Node 26, NestJS 11 (server), React 19 + Mantine 9 (client), Kysely, portainer-stack deploy via `scripts/deployportainer.sh`.

**Spec:** This plan IS the spec for the v0.96.0 merge. There is no upstream design doc to argue from — the plan enumerates every change between `v0.95.0..v0.96.0` and dictates resolution per file.

## Global Constraints

- **Base of merge = current `main` HEAD (`407c56ef`)** — 28 fork-specific commits on top of upstream `v0.95.0`.
- **Merge source = upstream tag `v0.96.0` (`9b3e5dd3`)** — 50 commits, 65 new files, no upstream deletions of our files.
- **Default resolution = keep local (fork).** Adopt upstream only when explicitly justified in the task ("Important" tag, requires user authorization).
- **No force pushes, no `git reset --hard`, no rewriting published history.**
- **Work happens on `merge/v0.96.0` branch in a dedicated git worktree.** `main` is not touched until verification passes.
- **Bump our version strings to `0.96.0` at the end** (`package.json`, `apps/server/package.json`, `apps/client/package.json`); fork name stays `boltplan`.
- **Lockfile resolution strategy = regenerate from `package.json`, do not hand-edit** (`pnpm install --no-frozen-lockfile` then commit).
- **Commit after every task**, conventional commits with scope (`merge`, `deps`, `ee`, `infra`, `fix`).
- **Translation files: 3-way merge from `git checkout --ours/--theirs`, then `node scripts/merge-translations.mjs` if it exists, otherwise hand-merge new keys only** — never overwrite a local string with an upstream one without checking the surrounding context.
- **The author (user) is the final arbiter for "Important" conflicts** — when a task says "ASK USER", stop and ask via `question` tool before proceeding.

cat > /tmp/json-merge.mjs <<'EOF'
import fs from 'node:fs';
const ours = JSON.parse(fs.readFileSync(process.argv[2], 'utf8'));
const theirs = JSON.parse(fs.readFileSync(process.argv[3], 'utf8'));
const out = { ...ours };
for (const [k, v] of Object.entries(theirs)) {
  if (!(k in out)) out[k] = v;        // take theirs-only keys
  // for keys in both, keep ours (fork has the curated wording for fork-specific strings)

const ordered = Object.keys(out).sort().reduce((a, k) => (a[k] = out[k], a), {});

EOF
